# Цифровой деканат

Учебный проект на **Next.js**, **Prisma** и **PostgreSQL**. В базе хранятся
учётные записи и сессии, данные студентов и групп, дисциплины, расписание,
оценки, заявки и уведомления. Проект включает главную Campus Today,
защищённую навигацию и страницы профиля. Доступны расписание, оценки, заявки,
персональные уведомления и сроки. Также есть серверная авторизация, тестовые данные и проверка
подключения к базе.

## Что установить

1. **Node.js 20.9 или новее** — рекомендуем Node.js 22 LTS. Вместе с ним
   устанавливается npm. Скачать: [nodejs.org](https://nodejs.org/).
2. **Git for Windows** — нужен, чтобы скачать проект. Скачать:
   [git-scm.com](https://git-scm.com/download/win).
3. **Docker Desktop для Windows** — запускает PostgreSQL. Установите и запустите
   Docker Desktop перед запуском базы.

Проверить установку можно в PowerShell:

```powershell
node --version
npm --version
git --version
docker --version
docker compose version
```

## Запуск с нуля в Windows

Откройте PowerShell или терминал в VS Code. Команды ниже предназначены для
PowerShell.

### 1. Скачайте проект

Например, сохраните его на рабочий стол:

```powershell
cd $HOME\Desktop
git clone https://github.com/gagarinazv-blip/digital-dean.git
cd digital-dean
```

### 2. Создайте файл настроек

Скопируйте шаблон:

```powershell
Copy-Item .env.example .env
```

Откройте `.env` в редакторе и задайте пароль базы: замените
`change_me_to_a_long_random_password` в `POSTGRES_PASSWORD` и в `DATABASE_URL`
на один и тот же пароль. Для простоты используйте только латинские буквы и
цифры. Не публикуйте и не отправляйте файл `.env`: в нём находятся настройки
подключения к базе. Задайте пароли из таблицы [демо-аккаунтов](./docs/DEMO.md)
в локальном `.env`. Они используются для начального наполнения демо-аккаунтов
и хранятся в базе только в виде bcrypt-хешей. Не добавляйте реальные пароли в
`.env.example`.

Для шифрования пароля демо-почты задайте `MAIL_CREDENTIALS_KEY`. Сгенерируйте
случайный ключ длиной 32 байта в Base64:

```powershell
node -e "console.log(require('node:crypto').randomBytes(32).toString('base64'))"
```

Скопируйте результат в `MAIL_CREDENTIALS_KEY` в `.env`. Не публикуйте этот
ключ и храните его неизменным: без прежнего ключа уже сохранённые пароли
расшифровать нельзя. Домен для демо-адреса задаётся необязательно через
`CORPORATE_MAIL_DOMAIN`; по умолчанию используется вымышленный
`mail.example.test`.

### 3. Запустите PostgreSQL

Убедитесь, что Docker Desktop запущен, затем выполните:

```powershell
docker compose up -d
docker compose ps
```

Подождите, пока у контейнера `db` появится состояние `healthy`.

### 4. Установите зависимости и подготовьте базу

В папке проекта по очереди выполните:

```powershell
npm install
npx prisma generate
npx prisma migrate dev
npx prisma db seed
```

Команды устанавливают библиотеки проекта, создают клиент Prisma, применяют
миграции и загружают вымышленные тестовые данные. Seed подтверждает завершение,
но не выводит учётные данные.

### 5. Запустите сайт

```powershell
npm run dev
```

Откройте [http://localhost:3000](http://localhost:3000). Оставьте это окно
терминала открытым, пока пользуетесь сайтом. Чтобы остановить сервер, нажмите
`Ctrl+C`.

## Проверка подключения к базе

Откройте [http://localhost:3000/api/health](http://localhost:3000/api/health).
Если подключение работает, ответ будет:

```json
{"status":"ok","db":"ok"}
```

Если база недоступна, endpoint вернёт статус HTTP 503 и безопасный ответ без
внутренних подробностей:

```json
{"status":"error","db":"error"}
```

## Демо-аккаунты

Телефоны и соответствующие переменные паролей для всех демо-студентов и
сотрудников приведены в [docs/DEMO.md](./docs/DEMO.md). Значения паролей
задаются только в локальном `.env`, в документацию и терминал они не выводятся.
Ввод телефона нормализуется; для ранее созданных аккаунтов без телефона
сохранён вход по прежнему логину и паролю.

Одноразовый SMS-код используется только для восстановления доступа. После
восстановления студент задаёт новый пароль и входит заново. Сотрудник может
задать начальный или новый пароль студента в разделе управления студентами.

Ссылка на матрицу прав: [docs/permissions.md](./docs/permissions.md).

Повторный `npx prisma db seed` атомарно пересоздаёт управляемые демо-аккаунты и
связанные с ними заявки, оценки, уведомления и расписание, не создавая
дубликаты. Seed сбрасывает ручные изменения этих фикстур; не запускайте его
ради обычного обновления пароля или на production-базе.
Для `student.alpha` seed создаёт расписание на сегодня и следующие шесть дней,
персональные уведомления и заявки в разных статусах. У `student.beta` есть
расписание на те же семь дней, уведомления, задания со сроками и заявки с
историей статусов. Сроки и связанные уведомления вычисляются относительно
`DEMO_NOW`; переменная принимает ISO-дату/время, а если не задана, используется
текущая дата.
Для этих же аккаунтов загружается учебный план на 2026/2027 учебный год,
оценки с историей попыток и расписание текущей сессии. Данные доступны в
разделе «Оценки».

Переносы хранятся в существующих полях `ScheduleItem` (`status`,
`originalStartsAt`, `originalEndsAt`, `originalRoom` и `changeNote`).
`Deadline` — отдельная сущность, так как в расписании и заявках нет модели
учебных заданий. В существующей таблице `Notification` остаются прежние
объявления; для новых событий добавлены UUID `publicId`, тип, цель и `readAt`.
Персональные события создаются с владельцем-студентом и используют этот UUID
во внешних ссылках. Страница перехода проверяет владельца уведомления и доступ
к его цели перед отметкой «прочитано».

## Тестовая формула оценки

В `src/lib/grade-formula.ts` находится демонстрационная формула для дисциплины
«Компьютерные сети» (`pi31-s5-networks`) у `student.alpha`; экзамен в фикстуре
запланирован на 16 ноября 2026 года. Баллы компонентов в формуле — только
пример для тестирования: фикстура содержит итоговые результаты, но не баллы
отдельных контрольных или лабораторных.

Формула распределяет 100% между контрольными работами (20% + 20%),
лабораторными (30%), активностью (10%) и экзаменом (20%). Экзамен обязателен,
автомат не предусмотрен. Итог округляется математически до целого только после
суммирования взвешенных компонентов: 0–54 — оценка 2 и не сдано, 55–74 — 3,
75–89 — 4, 90–100 — 5. Например, 74.5 округляется до 75, а 89.5 — до 90.

Чистая функция `calculateGrade(formula, scores)` принимает в `scores` новые или
гипотетические баллы, возвращает `missingComponents` и не выставляет итоговую
оценку, пока не получены все компоненты. Например, для проверки гипотезы можно
передать `{ exam: 18 }`; сохранённые в формуле демонстрационные баллы остальных
компонентов дадут итог 90 и оценку 5. Формула не требует миграции и не связана
с UI или базой данных; позже калькулятор сможет вызывать эту же функцию.

## Справки и заявки

Каталог услуг задан типизированной константой в
`src/lib/request-catalog.ts`: «Справка об обучении» и «Справка-вызов» используют
существующий тип заявки `CERTIFICATE`, а `catalogCode` различает услуги.
Общая проверка обязательных полей, допустимых значений, дат и длины находится
в `src/lib/request-validation.ts` и выполняется как в форме, так и на сервере.

Заявка сохраняет введённые поля и снимок профиля (ФИО, факультет,
направление, группа, курс, номер зачётной книжки и форму обучения). Студент
видит только свои заявки; публичный UUID используется в ссылках, а доступ к
записи дополнительно проверяется по текущей сессии. История статусов
сохраняется в `RequestStatusHistory` в той же транзакции, что и смена статуса.
Статусы ведутся централизованно в `src/lib/permissions.ts`: `NEW` может перейти
в `IN_PROGRESS` либо быть отменён студентом; `IN_PROGRESS` может перейти в
`NEEDS_INFO`, `READY` или `REJECTED`; `NEEDS_INFO` возвращается в
`IN_PROGRESS`. Только студент может отменить собственную заявку в статусе
`NEW`.

Пользовательские страницы: `/requests` — «Мои заявки»,
`/requests/new` — новая заявка, `/requests/<UUID>` — карточка и история.
Тестовые заявки для `student.alpha` и `student.beta` создаются повторно вместе
с остальными демонстрационными данными через `npx prisma db seed`.

## Серверная авторизация

Модуль `src/lib/auth.ts` предоставляет функции для серверного кода:

- `hashPassword` и `verifyPassword` используют bcryptjs с 12 раундами; открытый
  пароль в базе не хранится.
- `loginUser(login, password)` проверяет пароль, создаёт сессию и устанавливает
  cookie. Возвращает безопасный профиль без хэша пароля или `null` при неверных
  данных. Для неверного логина выполняется сравнение с фиктивным bcrypt-хэшем.
- `getCurrentUser()` читает cookie и возвращает пользователя только при наличии
  действующей сессии, иначе возвращает `null`.
- `deleteSession()` удаляет текущую сессию и cookie. Вызывайте функции,
  изменяющие cookie (`loginUser`, `createSession`, `deleteSession`), из Server
  Action или Route Handler.

Cookie HttpOnly, SameSite=Lax и Secure в production. Время жизни сессии
настраивается через `SESSION_TTL_MINUTES` (по умолчанию 60 минут, допустимо от
1 минуты до года). Ограничитель допускает не более пяти попыток входа за 15
минут для сочетания логина и IP-адреса; после успешного входа счётчик
сбрасывается. Для корректного ограничения за прокси настройте его так, чтобы
`x-real-ip` или `x-forwarded-for` содержали доверенный адрес клиента.

Для изменяющих запросов (создание заявки, ответ, смена статуса, назначение,
выход) дополнительно проверяется `Origin`: если заголовок есть, он должен
совпадать с текущим `host`. Это дополняет защиту SameSite=Lax: браузер не
отправляет cookie при кросс-сайтовом POST, а сервер в дополнение проверяет, что
исходный Origin принадлежит текущему домену. Если Origin отсутствует, код
сохраняет совместимость с локальными сценариями и обычными серверными
вызовами; основная защита всё равно остаётся в cookie и в проверках ролей.

Страница `/login` — единый вход для студентов и сотрудников. После проверки
учётной записи сервер направляет студента в его кабинет, сотрудника — в `/staff`.
Старый адрес `/staff/login` перенаправляет на `/login`. После выхода обе роли
возвращаются на общую страницу входа.

Для всех серверных разделов со студенческими данными используйте
`requireStudent()` из `src/lib/student.ts`. Функция проверяет текущую сессию,
при необходимости перенаправляет гостя на `/login` и запрашивает запись
студента только по `userId` из этой сессии. Она не принимает ID из URL или формы;
если у пользователя нет карточки студента, возвращается 404.

## Автоматические тесты

Запустите все тесты серверной авторизации командой:

```powershell
npm test
```

Тесты проверяют правильный и неправильный пароль, создание сессии, чтение
действующей и истёкшей сессии, отсутствие cookie, выход, блокировку после пяти
попыток, фиктивный хэш для неизвестного логина и привязку запроса данных
студента к пользователю из сессии. Prisma и API cookies изолированы подменами —
тесты не изменяют содержимое базы данных.

## Проверка сохранения данных

1. Если работает `npm run dev`, остановите его сочетанием `Ctrl+C`.
2. Остановите контейнеры, **не удаляя том с данными**:

   ```powershell
   docker compose down
   ```

3. Запустите базу снова:

   ```powershell
   docker compose up -d
   docker compose ps
   ```

4. Когда `db` снова будет `healthy`, запустите сайт командой `npm run dev` и
   откройте его или Prisma Studio (`npx prisma studio`).

Контейнер остановится и создастся заново, но данные останутся в Docker-томе
`pgdata`. **Не добавляйте `-v` к `docker compose down`**: флаг `-v` удалит том и
все сохранённые в нём данные.

## Частые ошибки

### Docker не запущен

Сообщение о невозможности подключения к Docker означает, что Docker Desktop
закрыт или ещё запускается. Откройте Docker Desktop, дождитесь его готовности и
повторите:

```powershell
docker compose up -d
```

### Порт базы уже занят

Если Docker сообщает, что порт `5432` занят, остановите другую программу,
использующую этот порт, либо задайте свободный порт, например `5433`, в
`POSTGRES_PORT` файла `.env`. В строке `DATABASE_URL` тоже замените порт после
`localhost:` на `5433`. Затем пересоздайте контейнер без удаления тома:

```powershell
docker compose down
docker compose up -d
```

Если занят порт сайта `3000`, остановите другую программу, использующую его,
или освободите порт и снова запустите `npm run dev`.

### PowerShell запрещает запуск npm-скриптов

Если PowerShell сообщает, что выполнение скриптов отключено (например, при
`npm` или `npx`), разрешите локальные скрипты для своей учётной записи:

```powershell
Set-ExecutionPolicy -Scope CurrentUser -ExecutionPolicy RemoteSigned
```

Подтвердите изменение, если PowerShell спросит, затем закройте и заново откройте
терминал и повторите команду. Это настройка для текущего пользователя Windows;
обычно запуск от имени администратора не нужен.

### `/api/health` возвращает ошибку

Проверьте, что Docker Desktop запущен, контейнер `db` имеет состояние
`healthy`, а миграции выполнены:

```powershell
docker compose ps
npx prisma migrate dev
```

### Не находится файл `@/generated/prisma/client`

Сгенерируйте клиент Prisma:

```powershell
npx prisma generate
```

## Таблицы базы данных

- `User` хранит логин, хэш пароля и роль.
- `Student` хранит ФИО, факультет, направление и курс; связан с учётной записью
  один к одному и с учебной группой.
- `StudentGroup` хранит группы студентов и используется для расписания и
  групповых уведомлений.
- `Subject` хранит дисциплину и преподавателя.
- `ScheduleItem` хранит занятие: дисциплину, группу, день недели или дату,
  время, аудиторию, преподавателя и отметку о переносе.
- `Grade` хранит оценку или зачёт конкретного студента по дисциплине.
- `Request` хранит заявку студента, её статус, комментарий и даты.
- `Notification` хранит объявления и персональные события; у событий есть
  публичный UUID, тип, цель и время прочтения. Старые объявления по-прежнему
  могут быть адресованы группе.
- `Deadline` хранит персональное задание, дисциплину, срок и статус сдачи.

Внешние ключи связывают оценки, заявки, дедлайны и персональные уведомления со
студентом. Серверные запросы и действия используют владельца из текущей
сессии; ссылка уведомления дополнительно проверяет доступность цели.
